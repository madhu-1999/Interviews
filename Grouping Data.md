# GROUPING SETS
>[!tip] Use case
> Used to fetch data for dashboards where you need to show the "_details_", "_subtotals_" and the "_grand totals_" in one view.

```sql
SELECT 
	c1, 
	c2, 
	aggregate_function(c3) 
FROM table_name 
GROUP BY GROUPING SETS ( 
	(c1, c2), 
	(c1), 
	(c2), 
	()
);
```

| **brand** | **segment** | **quantity** |
| --------- | ----------- | ------------ |
| ABC       | Premium     | 100          |
| ABC       | Basic       | 200          |
| XYZ       | Premium     | 100          |
| XYZ       | Basic       | 300          |

Consider this `UNION ALL` query:
```sql
-- NULL added since UNION ALL requires same number of columns, order of columns and datatype of columns.

-- Find quantity of products sold by brand and segment
SELECT 
	brand, 
	segment, 
	SUM (quantity) 
FROM sales 
GROUP BY brand, segment 

UNION ALL 
-- Find quantity of product sold by brand
SELECT 
	brand, 
	NULL, 
	SUM (quantity) 
FROM sales 
GROUP BY brand 

UNION ALL 
-- Find quantity of product sold by segment
SELECT 
	NULL, 
	segment, 
	SUM (quantity) 
FROM sales 
GROUP BY segment 

UNION ALL 
-- Find quantity of all product sold
SELECT 
	NULL, 
	NULL, 
	SUM (quantity) 
FROM sales;
```
 
This query generates a single result set with the aggregates for all `GROUP BY` clauses.

![[Pasted image 20260219190246.png]]
But there are two main issues with this:
1. Query is very lengthy
2. `UNION ALL` scans table 4 times (once per `SELECT`) to generate the result, which is slow.

A faster and more readable way of running this query is using `GROUPING SETS` .
Postgres optimizes no of scans and aggregates everything together simultaneously.
```sql
SELECT 
	brand, 
	segment, 
	SUM (quantity) 
FROM sales 
GROUP BY GROUPING SETS ( 
	(brand, segment), -- Group by both brand, segment
	(brand),  -- Group by brand only
	(segment), -- Group by segment only
	() ); -- No grouping. Aggregate function applies to entire column.
```

Note that this clause uses `NULL`  to represent "_ALL_".
Suppose a `segment` value is `NULL` in the data, total for a brand with a `NULL` segment  and the actual total for a brand is harder to tell apart at a glance.

This is where the `GROUPING` function helps. It returns 0 if value is member of current grouping set and 1 otherwise. We can use it to _flag_ which rows are totals.

```sql
SELECT 
    CASE WHEN GROUPING(segment) = 1 THEN 'All Brands' ELSE segment END AS segment,
    SUM(quantity)
FROM sales
GROUP BY GROUPING SETS ((brand, segment), (brand));
```

Now we will have two distinct pairs (brand, NULL) and (brand, All Brands).
# CUBE
>[!tip] Use Case
>Used to fetch data for dashboards where you need to show the "_details_", "_subtotals_" and the "_grand totals_" in one view.

```sql
SELECT 
	c1, 
	c2,
	c3, 
	aggregate (c4) 
FROM table_name 
GROUP BY CUBE (c1, c2, c3);
```

This subclause is **shorthand** for generating multiple grouping sets.

>[!note] 
>In general, if the number of columns specified in the `CUBE` is `n`, then you will have $2^n$ combinations.

```
CUBE(c1,c2,c3)
--is equivalent to 
GROUPING SETS ( 
	(c1,c2,c3), 
	(c1,c2), 
	(c1,c3), 
	(c2,c3), 
	(c1), 
	(c2), 
	(c3), 
	() 
)
```
## Partial CUBE
+ Used to reduce the number of grouping sets generated by the `CUBE` subclause.
+ By moving a column outside of the `CUBE` parentheses, you treat it as a constant grouping element.
```sql
SELECT 
	c1, 
	c2, 
	c3, 
	aggregate(c4)
FROM table_name
GROUP BY 
	c1, 
	CUBE(c2, c3);
```
This generates the combinations:
>(c1, c2, c3),
(c1, c2),
(c1, c3),
(c1)

Ex: Suppose you want to see sales data where the **brand** is always identified, but you want all sub-totals for the **segment**.
```sql
SELECT 
	brand, 
	segment, 
	SUM (quantity)
FROM sales
GROUP BY 
	brand, 
	CUBE (segment)
ORDER BY 
	brand, segment;
```

![[Pasted image 20260219234220.png]]
### Why use a Partial Cube?

- **Performance:** Generating fewer grouping sets requires less computational power and memory, which is critical for large datasets.
- **Relevance:** Often, a full cross-tabulation includes combinations that don't make sense for your specific business report.
- **Readability:** It produces a more focused result set that is easier for humans to parse.
# ROLLUP
+ Shorthand to generate multiple grouping sets, while assuming a hierarchy among input columns.
```sql
SELECT    
	c1,    
	c2,    
	c3,    
	aggregate(c4)
FROM table_name
--hierarchy is assumed to be c1 > c2 > c3
GROUP BY ROLLUP (c1, c2, c3); 
```
This generates the grouping sets:
> (c1, c2 ,c3)
> (c1, c2)
> (c1)
> ()

**Scenario: Hierarchical Sales Reporting**
When your data has a natural "parent-child" relationship. For example, if you group by `(brand, segment)`, `ROLLUP` will provide:
- Sales for each specific **brand and segment**.
- Subtotals for each **brand** (across all segments).  
- A **grand total** for all brands and segments combined.
```sql
SELECT 
	brand, 
	segment, 
	SUM (quantity)
FROM sales
GROUP BY ROLLUP (brand, segment)
```
![[Pasted image 20260220222805.png]]
**Scenario**: Time-Series Aggregation
Because time is inherently hierarchical, `ROLLUP` is perfect for financial or operational dashboards. You can create a single query that returns:
+ Daily counts.
+ Monthly totals.
+ Annual totals.
+ The overall total across all years.
## Partial rollups
Use if you want to group by one column strictly but roll up others.
```sql
SELECT 
	brand, 
	segment, 
	SUM (quantity) 
FROM sales 
GROUP BY 
	segment, 
	ROLLUP (brand);
```
This generates the combinations:
>(segment, brand) 
>(segment)
